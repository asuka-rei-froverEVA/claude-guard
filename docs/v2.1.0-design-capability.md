# v2.1.0 Design 能力通道兼容

## 背景

Claude Code 新能力可能已经包含在客户端中，但仍通过 Anthropic 账号侧功能开关
分阶段开放。`v2.0.4` 的官方 launcher 同时设置了：

- `DISABLE_TELEMETRY=1`
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`

Anthropic 官方环境变量文档说明，这两个变量都会停止功能开关下发。相同效果还可由
`DO_NOT_TRACK` 或 `DISABLE_GROWTHBOOK` 触发。结果是客户端二进制中即使已经包含
内建 `/design`，命令也可能不出现在自动补全中。

## v2.1.0 的选择

官方通道恢复第一方功能开关下发，但不放弃可以单独控制的保护：

| 项目 | v2.1.0 行为 |
| --- | --- |
| Anthropic 功能开关下发 | 允许 |
| 自动和手动客户端更新 | 关闭 |
| 错误上报 | 关闭 |
| `/feedback`、`/bug`、`/share` | 关闭 |
| 会话质量问卷 | 关闭 |
| 出口 IP / TLS / IPv6 门禁 | 保持 |
| OAuth / endpoint / profile / session | 保持 |
| 生命周期保护 / watchdog | 保持 |

launcher 继续使用 `env -i`。因此父 shell 或全局环境里残留的
`DISABLE_TELEMETRY`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`、
`DO_NOT_TRACK`、`DISABLE_GROWTHBOOK` 不会进入官方 Claude 进程。受守护的用户或
项目 settings 如果再次显式设置这些变量，仍会按 Claude Code 自身优先级生效，并
可能再次隐藏功能；配置文件中不应保留它们。

## 隐私边界

这不是“保持完全关闭 telemetry，同时只打开 `/design`”的技巧。Claude Code 当前把
功能开关拉取与 telemetry opt-out 绑定在一起，无法通过公开配置只恢复一个命令。

采用 `v2.1.0` 后：

- Anthropic 第一方功能开关、可用性检查和相关客户端事件可以恢复。
- 官方文档称默认 telemetry 事件不包含代码、文件路径或 shell 命令；本项目不把这
  一说明扩展成对所有网络请求内容的保证。
- 错误报告、主动反馈入口和会话质量问卷仍通过独立变量关闭。
- Guard 不拦截、不改写、不清洗 Claude 请求，也不移除客户端归因或规避平台策略。

如果“所有非必要流量必须关闭”优先于新能力，可以恢复旧总开关；代价是 `/design`
和其他依赖功能开关的能力可能消失。

## 保留的正常交互能力

`v2.1.0` 不把“官方新功能”本身视为风险，也不通过 Guard 强制关闭以下能力：

- 额度恢复后的自动续跑（`autoContinueAtUsageLimit`）。
- Prompt Suggestions 与 Session Recap。
- Auto 权限模式；Guard 不把它设为默认，也不从官方客户端中移除。
- 跨会话消息和 Claude.ai connectors；是否启用仍由用户设置与账号能力决定。

生命周期保护针对的是脱离当前 TUI 后仍可独立运行的会话、supervisor、Remote
Control、排程和路由绕过，不是普通前台交互。官方 settings 可以保留上述正常能力；
输入 `/exit` 后仍以“Claude 客户端、Guard 与受管后台进程均无残留”为实机验收门槛。

网络安全边界同样保持独立：功能开关是否开启，不得改变 `allowed_ips`、官方 endpoint
或本地 CONNECT 代理。固定出口由 Guard 启动门禁和 Clash/Mihomo 单一目标策略共同
约束，不依赖禁用 Prompt Suggestions、Recap 或 Auto。

## `/design` 与 frontend-design

- `/design` 是 Claude Code 内建的 Claude Design 画布入口，是否显示还取决于客户端
  版本、登录方式和账号侧开关。
- `frontend-design` 是官方 plugin marketplace 中独立的前端设计 skill。它会影响
  前端任务的提示与产出，但不会注册或解锁内建 `/design`。

## 验收标准

1. fixture 在父环境注入四类 capability blocker 后，fake Claude 进程中均不存在。
2. fake Claude 进程中存在更新、错误上报、反馈和问卷的精确关闭项。
3. 完整测试套件通过，正式入口预检仍通过。
4. 使用具备对应能力的候选客户端启动 TUI，仅输入 `/design` 不回车即可看到命令
   补全；这一步不发模型请求、不消耗模型额度。
5. 正式客户端版本与哈希指针不因本次 Guard 更新而自动改变。
6. 开启额度续跑、Prompt Suggestions、Session Recap 或 connectors 不会触发生命周期
   门禁；退出 TUI 后必须没有候选客户端或 Guard 残留进程。

Anthropic 文档同时提示：安装或升级后的首次会话可能只完成开关拉取，依赖开关的
能力要到下一次启动才出现。命令可见也只证明客户端与账号已收到能力，不保证服务端
始终可用。

## 回滚

回滚时同时恢复以下两项：

1. 上一版 `claude-guard` 可执行文件。
2. 上一版官方 `settings.json`。

恢复 `DISABLE_TELEMETRY=1` 和
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` 会重新关闭第一方功能开关下发；
网络路由、OAuth 凭据和 session 文件不需要迁移或删除。
