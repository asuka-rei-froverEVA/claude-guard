# v2.1.1 TUI 内后台子代理

## 目标

恢复当前 Claude Code TUI 内的 background subagent 与 background Bash，使并行调研、
长测试和工具任务不会强制阻塞主对话；同时继续阻止退出终端后仍可独立运行的会话。

## 能力边界

| 能力 | v2.1.1 |
| --- | --- |
| TUI 内 foreground subagent | 允许 |
| TUI 内 background subagent | 允许 |
| TUI 内 background Bash / `Ctrl+B` | 允许 |
| Agent View / `claude agents` | 关闭 |
| `--bg` / `/background` / supervisor | 关闭 |
| Remote Control / tmux 脱离入口 | 关闭 |
| cron / workflows / exit handoff | 关闭 |
| 子代理并发 / 嵌套 | 最多 `3` / 深度 `1` |

Claude Code 的公共变量 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` 同时控制 subagent 与
Bash 的 `run_in_background`、自动后台化和 `Ctrl+B`。因此无法只打开后台子代理而
继续全局关闭后台 Bash。`v2.1.1` 选择不设置该变量，并通过退出验收约束生命周期。

## 保持的 Fail-Closed

- `disableAgentView=true` 与 `CLAUDE_CODE_DISABLE_AGENT_VIEW=1` 继续生效。
- Guard 继续拒绝 `claude agents`、`--bg`、`--background`、`attach`、`respawn`、
  Remote Control 和 tmux/iTerm2 脱离入口。
- `CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF=1`、`CLAUDE_DISABLE_ADOPT=1`、cron、workflows
  与 MCP 自动后台化保持关闭。
- endpoint、OAuth、profile、IP、TLS、IPv6、客户端版本与哈希策略不变。

## 验收

自动测试必须证明：

1. fake Claude 环境中不存在 `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS`。
2. `--bg` 等 detached CLI 路径仍被 Guard 拒绝。
3. 其余生命周期、网络和版本策略测试全部通过。

实机测试先单独输入 `!` 进入 shell mode，再输入唯一标记的长时间任务；不要把完整的
`!sleep ...` 一次性注入终端，否则客户端可能把它当成普通 prompt。任务运行后用
`Ctrl+B` 转为后台，再执行 `/exit` 并选择 `Exit and stop tasks`。退出后必须同时满足：

- 标记任务不存在。
- 测试 Claude 进程不存在。
- 对应 Guard/watchdog 不存在。
- 不产生模型请求。

## 回滚

若发现退出残留或 TUI 稳定性回归，恢复 `v2.1.0` Guard 和 settings，并重新加入：

```json
{
  "env": {
    "CLAUDE_CODE_DISABLE_BACKGROUND_TASKS": "1"
  }
}
```

回滚不改变客户端版本、profile、OAuth、session 或网络出口。
